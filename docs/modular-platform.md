# پلتفرم ماژولار AyuMC — تصمیم و وضعیت

این سند برای صاحب پروژه است. شناسه‌ها و نام فیلدها انگلیسی مانده‌اند چون همان‌ها در کد و مانیفست قرار دارند.

## چه چیزی حفظ شد

پلتفرم قبلی حذف نشد. بستهٔ `.ayu`، ناظر پروسه، `dartaotruntime`، پروتکل IPC، SDK و چرخهٔ نصب/فعال/غیرفعال/به‌روزرسانی سر جایش است. تست‌های قبلی با قرارداد جدید دوباره سبز شدند.

## مرز سه لایه

**هسته** فقط کار ضروری شبکه را می‌کند: فریم بسته، هندشیک ۱٫۸٫۹، پاسخ status، و خواندن login start. بعد از login start اتصال با یک بستهٔ disconnect بسته می‌شود. این هنوز سرور قابل بازی نیست.

هسته رویداد عمومی بازی مثل `PlayerJoinEvent` تعریف نمی‌کند. تنها چیزی که بیرون می‌دهد دو primitive داخلی است:

- `core.session.handshake`
- `core.session.login`

پیشوند `core.` رزرو است. پلاگین نمی‌تواند مستقیم به آن مشترک شود.

**Event Pack** یک `.ayu` با `packageType: "event-pack"` است. در `events/` نصب می‌شود، primitive را می‌بیند و قرارداد عمومی منتشر می‌کند. نمونه: `examples/login_events` قرارداد `session.login_started` را از `core.session.login` می‌سازد. این بسته با سرور نصب نمی‌شود.

**پلاگین معمولی** در `plugins/` است و در مانیفست می‌گوید کدام قرارداد را لازم دارد. اگر تأمین‌کننده فعال نباشد، پلاگین `suspended` می‌ماند و وقتی Event Pack بیاید خودش بالا می‌آید. با غیرفعال شدن اجباریِ پک (`event disable --cascade`) دوباره معلق می‌شود.

`onEnable` رویداد بازی نیست. همان پروتکل کنترل قبلی است: `init` و `shutdown` بین میزبان و ورکر.

## پروفایل

شناسهٔ نسخه: `AyuMC-1.8.9-release`. ماینکرفت جاوا ۱٫۸٫۹، پروتکل ۴۷. انتخاب در `config/server.json` ذخیره می‌شود و از شروع بعدی اعمال می‌شود. فرمان کنسول: `profile list` و `profile select AyuMC-1.8.9-release`.

Event Pack باید در مانیفست همین پروفایل را نام ببرد. پک پروفایل دیگر رد می‌شود و چیزی روی دیسک نمی‌ماند.

## توزیع رویداد

هر قرارداد در مانیفست حالت تحویل دارد:

- `observational`: یک‌طرفه، دسته‌ای، صف محدود. اگر صف پر شود قدیمی‌ها حذف می‌شوند و به مصرف‌کننده `delivery.gap` می‌رسد. حذف بی‌صدا نیست.
- `coalesce`: فقط وقتی قرارداد اجازه داده و کلید مشخص است، مقدار جدیدتر جایگزین قبلی همان موجودیت می‌شود.
- `decision`: میزبان تا بودجهٔ قرارداد منتظر رأی می‌ماند. هر رد کافی است. اگر جواب نیاید، سیاست `onTimeout` همان قرارداد اعمال می‌شود (`allow` یا `deny`). انتظار بی‌نهایت وجود ندارد.

اگر هیچ مصرف‌کننده‌ای برای قراردادی نباشد، primitive مربوط به آن پک فرستاده نمی‌شود.

هر پک و هر پلاگین هنوز پروسهٔ جداست. هزینهٔ حافظهٔ قبلی (حدود ۱۴ مگابایت برای هر ورکر خالی) هنوز پایه است. ادغام چند پک در یک پروسه پیاده نشده؛ تا وقتی اندازه‌گیری خلافش را نشان ندهد، جدا ماندن پروسه خرابی را محدودتر نگه می‌دارد.

## امنیت

پروسهٔ جدا خرابی را محدود می‌کند، نه دسترسی به فایل و شبکه را. ورکر با همان کاربر سیستم اجرا می‌شود. امضا و سقف حافظهٔ سیستم‌عامل هنوز نیست.

## چه چیزی آزمایش شد و چه چیزی نه

روی ویندوز و Dart 3.13.4:

- رجیستری قرارداد، نصب پک، تحویل primitive به پلاگین، تعلیق وقتی پک خاموش می‌شود، رد پک پروفایل ناسازگار، رد دو پک با یک قرارداد، و شکست `onEnable` بدون آویزان کردن میزبان.
- هندشیک، status، ping/pong و login start پروتکل ۴۷، با سوکت واقعی.
- تست‌های قبلی پلتفرم پلاگین.

لینوکس اجرا نشده. ورود به دنیای بازی، حرکت، بلاک و چت پیاده نشده. ظرفیت ۵۰۰۰ بازیکن ادعا نمی‌شود؛ شنوندهٔ پروتکل فقط status و شروع لاگین را جواب می‌دهد.

## فرمان‌ها

```text
profile list
profile select AyuMC-1.8.9-release
event list | info | install | enable | disable [--cascade] | update | uninstall [--cascade]
plugin list | info | install | enable | disable [--cascade] | update | uninstall [--cascade]
contracts
```

`--cascade` پلاگین‌هایی را که قرارداد الزامی‌شان قطع شده معلق می‌کند. بدون آن، خاموش کردن پکِ مورد نیاز رد می‌شود.
